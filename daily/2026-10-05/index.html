01OllamaOllama v0.40.0：Apple Silicon 默认启用 MLX 推理

Ollama 近日发布 v0.40.0 版本，核心变化是在 Apple Silicon 设备上默认通过 MLX 运行时运行受支持的模型架构，无需用户额外配置即可启用 MLX 后端，从而调用 Apple Silicon 的神经引擎与 GPU 资源，提升端侧大模型推理的速度与能效。该版本同步扩展了模型库，新增 gemma4、qwen3.6、qwen3.5 以及 qwen3.8 等通用模型，并首次引入 Nimble、tev1、clef、clef-flash 等面向决策类任务的模型，同样支持 MLX 路径。官方表示，后续将继续测试并启用更多模型架构。MLX 是 Apple 面向 Apple Silicon 优化的机器学习框架，Ollama 将其作为默认推理路径，意味着本地大模型在 Mac 上的运行体验将进一步接近甚至超越此前基于 CPU 的方案。对于希望在 MacBook、iMac 等设备上离线部署 LLM 进行开发、研究或隐私敏感场景的用户而言，这一变化降低了使用门槛并提升了实际性能，同时也将吸引更多 MLX 生态模型适配 Ollama 平台。

05Agent智能体深度研究院ACL26：LLM批量处理为何表现下降，实例数比长度更关键

ACL 2026 收录的研究《Understanding LLM Performance Degradation in Multi-Instance Processing: The Roles of Instance Count and Context Length》系统考察了大语言模型在多实例批处理（MIP）场景下的性能退化机制。MIP 任务要求模型逐条处理一批输入并给出聚合判断，与一次仅处理一条的单实例处理（SIP）形成对照。研究首先筛选出在 SIP 设置下表现稳定的模型、任务和样本，以保证基线可靠，随后在仅改变批大小或上下文长度的对照实验中比较准确率变化。结果显示，即便单条处理时能够正确作答，模型进入多实例模式后仍会出现明显错误，说明问题并非源于输入长度本身，而是聚合多步中间结果这一过程的固有缺陷；进一步分析发现，实例数量对准确率的负面影响显著大于上下文长度的影响，表明模型在汇总多条独立推理结果时存在系统性瓶颈，而非单纯受制于上下文窗口。该结论对依赖批量调用 LLM 完成筛选、归纳与决策链路的 Agent 系统具有直接参考价值，提示在工程设计中应对批大小设置上限、引入分块校验或采用多次采样聚合等策略，以缓解聚合阶段的可靠性风险。
