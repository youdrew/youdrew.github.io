05AI Hot（卡兹克）OpenAI为前沿模型部署激活分类器

OpenAI 自 GPT-5.6 起在其最强模型的内部和外部流量上部署激活分类器（probes），利用模型内部激活逐 token 实时评分，可在生成中途阻断违规回复和工具调用并交由推理模型复审。实验显示 probes 比更大的文本分类器对测试的越狱攻击更鲁棒，准确率随模型能力提升，且在后训练各检查点间迁移良好，但需为新基础模型重新训练，且只能检测可显式训练的已知违规类型。 由于探针依赖被监控模型的激活值，新的基础模型需要重新训练探针，而且随着模型权重变化，可能也需要重新训练。 尤其是，每出现一个新的预训练基础模型，探针都需要重新训练。 即便在同一基础模型系列内，随着模型权重偏离训练探针时所用的检查点，探针性能也可能下降，因此需要定期重新训练[见迁移部分]。 因此，对每组超参数配置，我们通常至少训练 32 个随机初始化。 我们发现，需要扫描的关键超参数是学习率、激活来源层和架构容量。 由于探针权重相比其需要处理的训练激活值很小，训练主要受带宽限制。 在前沿模型上部署探针需要许多团队的广泛协作。

Crawl4AI作为内容准备层处理JavaScript渲染、选择性提取和自定义元数据增强，然后将网页内容送入Amazon S3数据源，供Amazon Bedrock Knowledge Bases使用。 Amazon EventBridge按配置的日程启动AWS Fargate上的Amazon ECS任务；该任务抓取已配置的公共网站，并为每个页面准备Markdown和元数据附属文件。 该工作流是对已知网站属性的批量摄取，并非在推理时进行实时网页访问。 Crawl4AI完成源文档和元数据附属文件的准备后，Amazon Bedrock KnowledgeBases负责解析、分块、嵌入、索引和检索。 Amazon Bedrock Web Crawler遵守robots.txt；首次完整抓取后，每次同步仅捕获新增、更新和删除的内容。 选择性提取仅提取可选CSS选择器匹配的页面区域。 Amazon OpenSearch Serverless向量索引必须使用faiss引擎。 使用Amazon S3 Vectors时，每个向量最多可附加1 KB自定义元数据，因此添加的属性应保持简短。 Amazon S3数据源必须使用为此工作流配置的S3存储桶。 如果数据源按前缀或文件模式过滤内容，过滤规则必须允许工作流写入s3Prefix下的文件，默认前缀为web-content/。 部署工作站仅用于构建和部署；部署完成后，定时任务在AWS中运行。
