03AI Hot（卡兹克）OpenAI加固前沿模型训练并开展红队测试

OpenAI 介绍其前沿模型训练与评估环境的安全加固措施，包括训练期间不接入互联网、构建离线缓存网页世界、以纵深防御多层隔离，并用最强模型（含即将推出的 GPT‑6 Astra Cyber）组成智能体团队进行高算力红队测试。 这些研究环境与客户使用我们已发布模型的环境不同：开发中的模型可能尚未完成安全与对齐训练，而且我们会刻意在对抗性条件下测试它们，以暴露弱点。 为了处理软件，AI 模型需要计算环境：即数字工作区，模型可以在其中编写和运行代码、搜索信息，并尝试不同的解题方法。 尽管我们控制住了该事件，但它暴露了需要进一步处理的弱点。 离线环境为智能体提供了无需访问实时互联网即可使用的资源，但我们还需要防止智能体越出这些环境。 随着模型越来越擅长发现和利用这些弱点，我们需要能够维持隔离的防御措施，即使模型成功击败了单个控制措施。 我们还为 macOS 和 Windows 使用虚拟化环境，并为需要加速器的任务使用带用户空间沙箱的 GPU 支持容器。 目前完全物理隔离（即完全断开与外部网络的连接）这一基础设施并不可行，因为我们需要外部连接来运行和监控实验。 这些限制延伸到可从主机直接或通过其他服务访问的服务，以确保智能体无法利用其中任何一个作为间接外逃路径。 我们使用了一些能力最强且对齐良好的模型，包括我们即将推出的 GPT‑6 Astra Cyber 模型和一个内部前沿模型。 我们智能体的虚拟机逃逸表明，隔离必须延伸到沙箱之外。

05Hacker NewsLLM正让形式化软件验证扩大规模

Hacker News 热议 · 442 分 · 287 条评论 Proofs can be many times larger than the original code, and writing them requires significant effort and a niche, highly specialized skill set. Accordingly, formal verification has been practical only in truly mission-critical applications, such as Airbus’s avionics code. Specifically, Claude proved that these programs will always exit normally without triggering memory-safety errors or failing assertions, for every input less than 64 MB and every modeled Linux operating system (OS) response and memory layout, under certain assumptions (namely that the program runs as a single-threaded static binary with a fixed memory budget on a RISC-V1 CPU using Linux OS). To prove that a piece of software is correct, we must first state what “correct” even means. To close that gap, we’d need to specify what callers must do for each public function, and callers would have to strictly adhere to it. We expect that as we learn more about leveraging LLMs for formal methods, and as models continue to improve, these limitations will become tractable, and we’ll be able to verify a much larger percentage of the code we rely upon. The trajectory is clear: formal verification, which was historically practical only for bespoke expert-crafted guarantees in the most safety-critical code, will soon be as practical as fuzzing is today for almost all production software. Just like static types, testing frameworks, and other correctness tooling, verification will mature from “bolted-on” to “built-in,” driven not only by LLMs but also by innovations in language design and development workflows. In today’s world—where LLMs automatically scan for and find increasingly more code vulnerabilities—we must use processes that can guarantee code security properties.

08IT之家OpenAI联合机构用数千AI智能体分析小鼠脑细胞

OpenAI 联合 PerturbAI 和斯克里普斯研究所（Scripps Research），利用数千个 AI 智能体分析数百万个小鼠脑细胞的生物学数据，整个分析过程耗时 32 分钟。 这项研究使用了专为生命科学研究设计的 GPT-Rosalind 模型，分析一份覆盖整个小鼠大脑的 CRISPR 图谱。 研究人员采用分布式 AI 智能体架构，将大量分析任务拆分后并行执行；每个智能体负责研究一种基因干预、分析相关细胞的反应并检索科学文献，为观察到的变化寻找可能的生物学解释。 研究人员将各智能体的报告整合为一份名为“Reasoning Atlas”的推理图谱，关联基因、细胞变化、参考文献和潜在作用机制。 在 20 组配对报告中，生物学专家在 75% 的评审中更倾向于分布式智能体生成的报告；单个智能体的报告获得 16.7% 的评审偏好，其余 8.3% 的评审结果为平局。 研究团队估计，如果由人类研究人员逐项分析实验结果并检索相关文献，完成同等工作可能需要数月到一年。 相关研究论文已于 2026 年 10 月 16 日发布在 bioRxiv 预印本平台，目前尚未经过同行评审。 AI 提出的生物学联系和作用机制仍属于有待验证的研究假设，后续仍需通过实验确认。
