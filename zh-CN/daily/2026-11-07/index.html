06IT之家苹果披露HALO人形机器人控制系统

苹果研究团队在预印本平台 arXiv 提交论文《Perceptive Humanoid Motion from Simulation》，披露了人形机器人自主控制系统 HALO。 研究团队公开了数据生成、模型训练和部署代码，涵盖动作生成、动作跟踪、任务编排以及仿真和真实机器人运行等环节。 HALO 的落地阶段采用宇树科技 G1 人形机器人，背部加装了专用 3D 打印保护外壳，内置一台配备 M4 Pro 芯片和 64GB 统一内存的 Mac mini。 执行任务时，HALO 由三个层级协同控制：最上层是基于视觉语言模型（VLM）的任务编排模块，中间是动作生成层，底层是经强化学习、策略蒸馏等步骤训练的动作跟踪器，以每秒 50 次的频率运行。 据论文披露，研究团队在 6 个未预先扫描或建图的真实环境中开展 360 次单项任务测试，平均成功率为 91%。 HALO 最上层任务编排模块默认采用千问 Qwen3.6-35B-A3B，也可选择通过 API 调用云端模型；中间的动作生成层采用千问 Qwen3.5-2B。 针对长序列复合任务，在单一真实场景，各进行 10 次测试，3 种组合平均成功率为 70%；其中最复杂的“俯身通过障碍 — 走向目标 — 推箱子”10 次测试成功 5 次，成功率为 50%。 仿真生成数据并未完全摆脱人工参与，新增物理任务仍需人工编写提示词、设计动作关键帧，部分动作还使用了人类视频或动捕素材。 目前机器人主要依赖视觉感知，难以直接感知接触情况；当物体离开相机视野或被遮挡时，涉及较多接触的任务表现会下降，加入触觉感知将是后续改进方向之一。 文内含有的对外跳转链接（包括不限于超链接、二维码、口令等形式），用于传递更多信息，节省甄选时间，结果仅供参考，IT之家包含外链的文章均包含本声明。

量子位为什么每个 Personal Agent 背后，都必须配备一台“云电脑”？

PPIO 沙箱，把“云电脑”做成开箱即用的 API 为什么每个 Personal Agent 背后，都必须配备一台“云电脑”？ 以 Manus 为例，上一代的 Manus 是任务式 Agent：用户提一个需求，它开一台虚拟机，跑完、交付、回收，一切随任务结束归零。 Manus 官方自己也承认，「每次常规聊天都从零开始，它无法访问你昨天做的事情」。 其次，基于以用户为中心为前提，Personal Agent 需要支持长时间运行。 能动手，就需要一台「手」能够着的电脑。 大脑负责理解需求、拆任务、决定调什么工具、管理授权和记忆，由模型加调度层组成，像 OpenClaw 的 Gateway 和 Muse 的 Sentinel； 02 每个 Personal Agent 背后都需要一台“云电脑” 更重要的是，本地运行的机器通常无法一直在线，一旦电脑关机或者休眠，Agent 即停止工作。 从这一点来说，这类方案无法满足 Personal Agent 长时间运行的需求。 PPIO 也推出了自己的云端沙箱托管方案 PPClaw、PPHermes，一键部署，十分钟上线，需要时随时在线，不用时暂停即停费。 大厂通常把「执行环境」当作产品内部实现，规格都不公开，开发者想复刻这套体验，必须自己找执行层。 PPIO 沙箱作为专为 Agent 打造的云端执行环境，为 Personal Agent 开发者量身定制了至少五项核心能力： 第三，执行环境要即开即用、可复制，少配环境是用户愿意付费的点。 自托管 OpenClaw 需要 Node.js 22+、一台 VPS、30 到 60 分钟配置； Kimi Claw 把它变成「浏览器标签页，即时」就能卖 199 元/月——开发者愿意为「少配环境」付费。
