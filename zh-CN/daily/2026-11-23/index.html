02IT之家OpenAI首席科学家提议限制先进模型开发

OpenAI 首席科学家雅库布·帕霍茨基提议，AI 企业应建立行业统一标准，对先进 AI 模型开发设置共同限制，并在研究人员具备更可靠的模型行为理解和监控能力之前不突破约定门槛。 帕霍茨基认为，传统 AI 能力评测基准会随技术进步迅速过时，困惑度可作为衡量模型预训练进展的参考指标，数值越低代表模型预测下一个文本 Token 的能力越强。 OpenAI 内部评测数据显示，GPT-3.5 的对数困惑度约为 0.99，GPT-4 约为 0.91；指标低于 0.8 时，OpenAI 观察到模型在网络安全和数学领域出现新能力，指标达到约 0.76 时，模型开始在部分开放数学问题上取得突破性成果。 帕霍茨基预计，对数困惑度进入 0.68 至 0.7 区间时，模型可能出现更多变革性能力，但目前无法确定这些能力具体是什么。 帕霍茨基警告，AI 最早可能在 2027 年推动预训练技术出现一轮快速进展，而模型对齐和行为监控方面的进展可能无法同步跟上；按其设想，各家 AI 企业应共同建立模型评测、透明度和安全红队测试标准，并在模型首次投入使用前完成相应评估。 困惑度并非完美指标；不同企业的训练数据和评测数据集存在差异，导致模型数值难以直接比较，而且困惑度无法直接对应具体任务能力，也不能完整反映思维链推理等预训练之外的技术进步。 OpenAI CEO 萨姆·奥尔特曼公开支持该提议，称帕霍茨基的文章是 OpenAI 一段时间以来发表的最重要内容之一之一，并希望 AI 行业就共同限制达成一致。 据美联社报道，民主党计划在 2027 年 1 月取得国会多数地位后，将 AI 列为优先议题，讨论数据中心监管、安全标准、加强技术监控和研究，以及要求 AI 企业接受第三方评估等。 美国总统特朗普一直反对对 AI 开发施加广泛限制，这可能使白宫与新一届民主党主导的国会在 AI 监管问题上产生分歧。

06IT之家美国初创企业公布 AI 自研 CPU 架构 Frostbite，能效是传统处理器的 4.59 倍

IT之家 11 月 22 日消息，美国加利福尼亚州帕洛阿尔托的初创公司 Architect Labs 在一篇研究博客中宣布，其人工智能系统已经自主发现、设计并验证了一款名为 Frostbite 的通用 CPU。这款处理器采用全新的指令集，从底层开始重新设计，试图摆脱传统 CPU 的部分架构限制。 在 25 项工作负载测试中，由 4 个计算单元组成的 Frostbite 集群， 每瓦性能达到一款尺寸相近、已经完成硅验证的双发射顺序执行 CPU 核心的 4.59 倍 。不过，这些数据来自基于 7 纳米工艺的模拟设计，Frostbite 尚未真正流片，因此还没有实际芯片可以验证。由于法律方面的原因，Architect Labs 暂时无法公开作为对照的 CPU 核心型号。 传统 CPU 需要在运行时通过硬件判断不同指令之间的依赖关系，重新识别哪些指令可以并行执行。多核处理器还需要复杂的多级缓存体系和缓存一致性协议，确保每个核心看到的共享内存数据保持一致。不过，这些机制不仅占用芯片面积、消耗电力，也会在处理器规模扩大时面临扩展效率下降的问题。 IT之家注意到，Architect Labs 提出的替代方案被称为“免费多线程”（Multithreading for Free）。其核心思路是让程序本身直接暴露可以并行执行的工作，而不是依赖传统线程、锁机制或乱序执行硬件，在运行过程中寻找并行机会。 不过，团队仍然提前确定了处理器需要重点优化的工作负载。 确定架构方向后，AI 智能体不再依赖英语描述硬件规格，因为团队认为，自然语言无法准确表达所有细节，也难以发现其中的错误。 每项修改都必须经过规格验证、快速模型测试、电路设计实现和功耗测量，只有通过各项检查的方案才会被保留。 此外，系统还意外出现了一种人类设计者从未明确规定的行为，即所谓的“工作窃取”（Work Stealing）：当某个 Tile 没有任务可执行时，可以从相邻 Tile 获取尚未完成的工作； 不过，Redwood 目前也只在 FPGA 上运行，尚未制造出实际芯片。 公司称，正在推进与台积电（TSMC）合作的流片计划。 Architect Labs 表示，未来还将公布更多性能测试结果，但这只是其计划的一部分。 最终，公司计划公开 Frostbite 的 RTL 设计代码和指令集。 在性能评估方面，Architect Labs 还计划扩大测试工作负载范围，并引入更多 CPU 作为对照，包括将更大规模的 Frostbite 网格架构，与配备大容量缓存的多核版本对比。 此外，公司还计划与规模更大、指令执行宽度更高的乱序执行 CPU 展开比较。 需要注意的是，目前 Frostbite 公布的性能优势仍然来自模拟设计，尚未经过实际硅芯片验证。 它能否在真正制造出来后保持这些能效优势，还需要后续流片和实测结果给出答案。

IT之家 11 月 22 日消息，美国加利福尼亚州帕洛阿尔托的初创公司 Architect Labs 在一篇研究博客中宣布，其人工智能系统已经自主发现、设计并验证了一款名为 Frostbite 的通用 CPU。这款处理器采用全新的指令集，从底层开始重新设计，试图摆脱传统 CPU 的部分架构限制。 在 25 项工作负载测试中，由 4 个计算单元组成的 Frostbite 集群， 每瓦性能达到一款尺寸相近、已经完成硅验证的双发射顺序执行 CPU 核心的 4.59 倍 。不过，这些数据来自基于 7 纳米工艺的模拟设计，Frostbite 尚未真正流片，因此还没有实际芯片可以验证。由于法律方面的原因，Architect Labs 暂时无法公开作为对照的 CPU 核心型号。 传统 CPU 需要在运行时通过硬件判断不同指令之间的依赖关系，重新识别哪些指令可以并行执行。多核处理器还需要复杂的多级缓存体系和缓存一致性协议，确保每个核心看到的共享内存数据保持一致。不过，这些机制不仅占用芯片面积、消耗电力，也会在处理器规模扩大时面临扩展效率下降的问题。 IT之家注意到，Architect Labs 提出的替代方案被称为“免费多线程”（Multithreading for Free）。其核心思路是让程序本身直接暴露可以并行执行的工作，而不是依赖传统线程、锁机制或乱序执行硬件，在运行过程中寻找并行机会。 不过，团队仍然提前确定了处理器需要重点优化的工作负载。 确定架构方向后，AI 智能体不再依赖英语描述硬件规格，因为团队认为，自然语言无法准确表达所有细节，也难以发现其中的错误。 每项修改都必须经过规格验证、快速模型测试、电路设计实现和功耗测量，只有通过各项检查的方案才会被保留。 此外，系统还意外出现了一种人类设计者从未明确规定的行为，即所谓的“工作窃取”（Work Stealing）：当某个 Tile 没有任务可执行时，可以从相邻 Tile 获取尚未完成的工作； 不过，Redwood 目前也只在 FPGA 上运行，尚未制造出实际芯片。 公司称，正在推进与台积电（TSMC）合作的流片计划。 Architect Labs 表示，未来还将公布更多性能测试结果，但这只是其计划的一部分。 最终，公司计划公开 Frostbite 的 RTL 设计代码和指令集。 在性能评估方面，Architect Labs 还计划扩大测试工作负载范围，并引入更多 CPU 作为对照，包括将更大规模的 Frostbite 网格架构，与配备大容量缓存的多核版本对比。 此外，公司还计划与规模更大、指令执行宽度更高的乱序执行 CPU 展开比较。 需要注意的是，目前 Frostbite 公布的性能优势仍然来自模拟设计，尚未经过实际硅芯片验证。 它能否在真正制造出来后保持这些能效优势，还需要后续流片和实测结果给出答案。
