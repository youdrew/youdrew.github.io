Mojo 语言正式开源，编译器与工具链全面开放

Mojo 由 Modular 公司打造，是面向 AI 高性能计算场景的编程语言，定位为 Python 的超集并兼容其生态，同时引入系统级语言的底层控制能力，长期被社区视为 Python 加速与 AI 基础设施层的潜在替代方案之一。Mojo 上周刚发布 1.0 源码稳定版本，此次开源采用 Apache 2.0 许可证并附加 LLVM 例外条款，编译器、工具链及全部相关源码同步在 GitHub 的 modular 仓库公开，意味着开发者和企业可以在生产环境中自由使用、集成和分发 Mojo，而不仅限于此前的预览与试用。不过目前 Mojo 编译器尚不接受外部代码贡献，Modular 表示计划在年底前正式开放贡献通道，标准库则自 2024 年起就已对外部开发者开放。对于 AI 工程师而言，Mojo 的全面开源降低了在其项目中评估和接入该语言的门槛，也让编译器层面的二次定制和内部审计成为可能；同时也使 Mojo 直接对标 Python 生态中的其他加速方案，其后续社区活跃度与生态扩展速度，将成为判断这门语言能否走出小众、进入主流 AI 工程栈的关键观察点。

智能体记忆并非越多越好：八款模型评测揭示剂量校准

近期一项针对八款主流智能体模型的对比评测揭示了一个反直觉的结论：记忆注入的多少并不能一概而论，而应依据模型自身能力做精细化剂量校准。在实验设计上，研究者并未采用更新模型权重或人工标注等高成本路径，而是从智能体过往执行轨迹中自动蒸馏出操作指南，并在推理阶段按需注入，从而在零额外训练的前提下测试不同模型的响应差异。结果显示，强能力模型如 DeepSeek-V3.2（671B MoE）能够充分消化完整的指南集，任务完成率提升 9.5 个百分点；与之相对，能力较弱的 gpt-oss-120b（117B MoE）在面对全量注入时反而出现收益递减，改用精选检索后，完成率跃升 16.1 个百分点，同时 token 开销仅增加约 5%。这一分化表明，记忆机制并非简单的"开关"，而是一道需与模型容量匹配的算术题。其意义在于为智能体的记忆系统设计提供了可量化的新范式。

09arXiv

自改进智能体的脆弱性：方差、任务顺序与欠规范问题

基于记忆库的自改进智能体——即通过维护文本记忆库从在线任务流中学习并随时间持续改进的一类方法——近年在文献中被视为颇具前景的方向，但其可靠性问题长期被忽视。研究者对两类典型基于记忆的方法展开系统再评估，从两个维度扩展实验：一是引入多次独立运行以量化方差，二是随机打乱任务呈现顺序以检验顺序敏感性。实验结果显示，这类方法的性能对任务出现顺序和不同的随机初始化均高度敏感，暴露出自改进范式存在显著的可靠性与欠规范化缺陷。这一发现意味着，先前报告的增益可能部分源于评估协议的宽松——例如固定任务顺序或单次运行带来的偶然优势，而非方法本身的稳健能力。因此，呼吁未来在评估自改进智能体时采用更严格的协议：多次随机种子运行、随机化任务顺序、报告方差，从而得出可重复、可推广的结论。
