07量子位DeepSeek开源Agent底座架构

量子位于2026-10-31发布文章，称DeepSeek公开了Personal Agent的底层架构思路，文章标题为“Super-agent：迈向更自主的Agent系统”。 DeepSeek团队称，在模拟多任务环境中，Super-agent的任务完成时间中位数为12.4分钟，95分位数为15.7分钟，表现优于测试中的传统单会话方案。 DeepSeek为Super-agent设计了双层架构，上层Router负责接收消息、分配任务和维护全局上下文，下层Worker负责具体执行，多个任务可以同时推进。 DeepSeek设计了两级事件过滤机制，先通过程序规则筛除无关消息，再由大模型判断剩余事件是否需要采取行动，以减少不必要的Token消耗。 DeepSeek团队的初步实验模拟了包含约300条消息、20项工作请求的协作环境，对比Super-agent与传统单Session加Subagent方案，每种配置重复测试5次；Super-agent任务完成时间中位数为12.4分钟、95分位任务完成时间为15.7分钟，传统单Session方案在中性提示下的95分位任务完成时间达到29.5分钟。 在日常软件开发过程中，开发人员经常碰到的一个问题是，需要在不同平台之间来回切换。 投机执行是AI发现某件事可能需要处理时提前在后台尝试；如果未找到有效结果，Agent可以保持安静以避免打扰。 DeepSeek设计了订阅与直通机制；某个Worker接手一条GitHub PR后可直接订阅后续评论，修改意见可直接交给该Worker处理，无需再经Router层层转发。 当Agent同时接入工作群、GitHub、邮件等平台时，大量消息会持续涌入，但真正需要处理的可能只有少数。 异步ReAct Loop机制已在DeepSeek Harness中实现，但尚未默认开启。 当AI逐渐能够独立完成复杂任务时，如何让它长期、稳定地推进多项工作，也开始成为Agent系统需要解决的新问题。

10AI Hot（卡兹克）OpenRouter发布AI代码审查脚本教程

OpenRouter 发布教程，介绍一个 233 行、仅用标准库的 review.py，通过 Responses API 组合 Files API、Shell 沙箱工具和 Apply Patch 工具，把变更文件上传到托管 Linux 沙箱，让模型实际运行检查确认 bug 并返回 V4A 补丁。 只读 diff 的审查器不得不猜测文件其余部分长什么样，以及怀疑的缺陷在运行时是否真的会失败，而且它给出的修复建议是以文本形式返回，需要你手动复制进去。 每个发现返回时都标记为 confirmed（附上证明它的命令和输出）或 unconfirmed（当缺陷无法用简短脚本展示时）。 Files API（测试版）：上传每个改动文件在变更后的完整内容、你传入的任何额外上下文文件（例如测试）以及 Git diff。 Shell 服务器工具（openrouter:shell，测试版）：在第一条命令运行前，把上传的文件复制到托管 Linux 容器的主目录，这样任何模型都能对你的代码运行 Python 和 SQLite。 Apply Patch 服务器工具（openrouter:apply_patch，测试版）：让模型以 V4A diff 形式提出文件改动（create_file、update_file、delete_file）。 脚本从 Git 获取 diff 和改动的文件名，加上任何 --context 文件，并把它们上传到 /api/v1/files（最多 19 个文件加 diff，符合每次请求 20 个文件的限制）。 Files API 不单独收费（每个文件上限 100 MiB，每个工作区上限 10 GiB，工作区文件不会过期）。 默认情况下，沙箱没有出站互联网访问，因此模型无法运行 pip install。 如果你的检查需要 PyPI 中的包，可以在 shell 工具上设置 network_policy，将 pypi.org 和 files.pythonhosted.org 等主机加入允许列表。
